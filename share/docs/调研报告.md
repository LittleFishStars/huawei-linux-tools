# 华为分享（Huawei Share）搬到 Arch Linux —— 调研报告

- 调研日期：2026-10-18
- 目标机器：HUAWEI MateBook X Pro（MRGF-XX），Arch Linux，内核 7.2.10-arch1-1
- 目标：让华为手机与这台 Linux 电脑能像 Windows 上的「华为分享」那样互传文件
- 关联项目：[`huawei-ntag0001-nfc`](../../huawei-ntag0001-nfc)（同一台机器上 NFC 接触口的逆向，结论是 RF 侧可用、主机侧读不到 EEPROM）

---

## 0. 结论速览

**不需要「移植」——华为官方就提供 Linux 版分享引擎（Share Engine / Share Kit）。**
真正的卡点是：它的核心库 `libsharekit.so` 是闭源的，只能凭华为开发者账号从官方文档站下载，全网没有任何公开副本。

| 路线 | 可行性 | 结论 |
|---|---|---|
| ① 用华为官方 **Share Engine Linux SDK** | ✅ 正解，**有账号门槛** | 拿到 `libsharekit.so` 即可让手机在「华为分享」里发现这台 Linux 电脑并传文件 |
| ② 社区重实现华为分享协议 | ❌ 无现成成果 | GitHub 全量代码搜索无任何实现；服务 UUID `0xFE35`、GATT 握手、Wi-Fi P2P 全部要自己啃 |
| ③ 第三方局域网互传替代 | ✅ 今天就能用 | LocalSend / KDE Connect；或 SMB，让手机「文件管理」原生访问电脑 |
| ④ 把 Windows 版电脑管家塞进 Wine | ❌ 物理上不可行 | 它依赖 `SpbNfcDriver.sys` 内核驱动 + WDF，Wine 不提供内核态执行环境 |

---

## 1. 华为官方确实有 Linux 版分享引擎

官方 Codelab：**Share Engine - Linux Devices**
<https://developer.huawei.com/consumer/en/codelab/ShareEngine-Linux/index.html#0>

原文要点（节选）：

> As a cross-device file transfer solution, HUAWEI Share Engine uses Bluetooth to discover nearby devices and authenticate connections, then sets up Wi-Fi peer-to-peer channels to allow file transfers between phones, PCs, and other devices. File transfer speeds can reach 80 Mbps if the third-party device and environment allow.
>
> Three SDK development packages are offered to allow integration for **Android, Linux, and Windows** based apps and devices.

官方样例仓库：<https://github.com/huaweicodelabs/ShareEngine>（Apache-2.0），`Linux/` 目录：

```
Linux/
├── Makefile                 # 官方构建脚本（参考用）
├── README-Linux             # 说明
├── sharekit_api.h           # 北向 API：InitShareKit / StartShareService / TransFile ...
├── sharekit_def.h           # 数据结构与回调定义
├── driver_adapt.h           # 南向适配层接口（厂家自行实现）
├── driver_ble_rx.c          # 南向参考实现：接收端（BLE GATT server）
├── driver_ble_tx.c          # 南向参考实现：发送端（BLE GATT client + scan）
├── sharekitdrx.c            # 接收端 demo
└── sharekitdtx.c            # 发送端 demo
```

也就是说：**北向 API + 南向 BlueZ 参考实现都是源码给的，只有中间那层协议栈（`libsharekit.so`）是二进制。**

## 2. 北向 API（`sharekit_api.h`）

```c
int  InitShareKit(void* handle);
int  StartShareService(ShareRole role, void* handle);   // RECEIVER=1 / TRANSMITTER=2
int  StopShareService(void);
int  GetAvailableDevice(ShareDeviceInfo** devInfo, int* devNum);
int  TransFile(const ShareDeviceInfo* device, const ShareFileInfo* files);
void CancelTransFile(void);
int  ConfirmRecvFile(const char* path);
void RefuseRecvFile(void);
int  UninitShareKit(void);
```

接收端典型用法（官方 `sharekitdrx.c`）：

```c
ShareRecvHandle recvHandler = {0};
recvHandler.progressCb = SharekitProcessCbFunc;   // 进度 0-100
recvHandler.statusCb   = SharekitStatusChangeCbFunc;
recvHandler.previewCb  = RequestFileTrans;        // 收到「要传这些文件」，决定收/拒
recvHandler.finishCb   = FileTransferResult;      // 传完
InitShareKit(NULL);
StartShareService(RECEIVER, &recvHandler);
// ... 等到回调通知结束
StopShareService(); UninitShareKit();
```

版本字符串（写死在库里，用于确认拿到的 SDK 对不对）：`sharekit-device-linux-1.0.0.100T1`。

## 3. 南向适配层（`driver_adapt.h` + `driver_ble_rx.c`）

### 3.1 关键协议常量（从官方参考实现里读出来的）

`driver_ble_rx.c` 头部：

```c
#define UUID_NEARBY_SERVICE                0xfe35
#define UUID_NEARBY_CHARACTERISTIC_EXCHANGE 0x2a00
#define UUID_NEARBY_CHARACTERISTIC_NOTIFICATION 0x2a01
```

- **华为 Nearby / 分享 的 GATT 服务 UUID = 0xFE35**
- 交互特征 `0x2A00`、通知特征 `0x2A01`
- 手机侧「华为分享」就是靠扫描这个服务的广播发现对端设备的

### 3.2 通道模型

`driver_adapt.h` 定义的通道枚举与事件：

```c
CHANNEL_BLE / CHANNEL_BREDR / CHANNEL_P2P / CHANNEL_USB
EVENT_CONNECT / EVENT_CONNECT_FAIL / EVENT_DISCONNECT
```

- **发现与认证**：BLE GATT（`0xFE35`）
- **传文件**：Wi-Fi P2P（`CHANNEL_P2P`），带宽 80 Mbps 量级

### 3.3 一个很硬的坑：demo 依赖 BlueZ 内部头文件

`driver_ble_rx.c` 并非只用 BlueZ 的公开 D-Bus API，而是直接 include BlueZ 源码树内部：

```c
#include "lib/bluetooth.h"
#include "lib/hci.h"
#include "lib/hci_lib.h"
#include "lib/l2cap.h"
#include "src/shared/mainloop.h"
#include "src/shared/att.h"
#include "src/shared/gatt-db.h"
#include "src/shared/gatt-server.h"
```

官方 Makefile 因此链接的是 BlueZ **内部静态库**：

```make
LIBS_W += -lpthread -lshared-mainloop -lbluetooth-internal -lcrypto -lsharekit
```

并且它假定你已经把 BlueZ 5.52 编在 `./thirdpart/gcc/bluez-5.52/`。

**结论：用 Arch 仓库里的 bluez 是编不出来的，必须自己把 BlueZ 5.52 源码编译一份。** 本仓库的 `scripts/build.sh` 已经把这一步自动化。

### 3.4 Wi-Fi P2P 走的是 wpa_supplicant

日志里能看到 `wpa_p2p_impl.c`、`Init wpa p2p` —— 也就是说 **Share Engine 自己实现了一套对 wpa_supplicant 的调用**，不走 NetworkManager。

> 本机目前用的是 **iwd**（`/net/connman/iwd/0 wifi-p2p`），`wpa_supplicant.service` 是 inactive。要跑 Share Engine，需要切换到 wpa_supplicant with P2P。

## 4. 卡点：`libsharekit.so` 闭源且有获取门槛

### 4.1 官方页面实测：SDK 不是「下载」，是「邮件申请」（2026-10-18 截图确认）

用户打开 [Obtaining the Linux SDK](https://developer.huawei.com/consumer/en/doc/connectivity-Library/sdk-download-linux-0000001052056169)
看到的原文（页面 `Last updated: 2021-03-24 16:29`），共三步，**没有任何下载按钮**：

> **Before obtaining the Huawei Share Engine Linux SDK, perform the following steps:**
>
> 1. Check whether your app and device meet the Share Engine Integration specifications for Linux.
> 2. **Download and fill in the `HUAWEI Share Engine Project Cooperation Specifications Survey (new).xlsx`
>    and send it via email to `devConnect@huawei.com` to apply for the SDK.**
>
> | SDK Version | Description |
> |---|---|
> | 1.0.0.100 | This SDK enables file transfer between a Huawei phone and a Linux device. |

三条硬信息：

1. **渠道是 B2B 商务申请，不是自助下载。** 流程是「下载 xlsx 合作调研表 → 填好 → 发邮件给 devConnect@huawei.com
   → 等华为审核并回传 SDK」。审核对象是**项目/公司**（Project Cooperation），不是个人账号。
2. **SDK 版本恒为 `1.0.0.100`**，与官方 demo 里 `sharekit_def.h` 的版本串
   `sharekit-device-linux-1.0.0.100T1` 完全吻合 —— 交叉验证通过，说明 demo 就是配套这一版。
   页面自 2021-03 未更新，说明这条线六年没再迭代，也没开放过公开下载。
3. 这一步解释了为什么全网找不到 `libsharekit.so`：**它从来没有公开可下载的通道**。此前 §3 的全网排查
   （GitHub 代码搜索 / AUR / Arch 官方库 / Gitee / CSDN / 本机 find）之所以一无所获，根因就在这里。

### 4.1.1 对个人用户的现实含义

| 路径 | 可行性 | 说明 |
|---|---|---|
| 发邮件申请 SDK | 极低 | 表格要求填项目名称、公司、预期出货量、集成场景；个人自用需求基本不会被受理 |
| 抓一个厂商的 `libsharekit.so` | 低 | 需要有人已经拿到并外泄；该库闭源、受协议约束，公开渠道无副本 |
| 放弃官方 SDK，走等价协议 | 高 | 见 [docs/替代方案.md](替代方案.md)：LocalSend（局域网直传，手机端有官方 app），当天可用 |

**结论**：这条线对个人用户是关闭的。`scripts/build.sh` 与 demo 移植仍然保留 —— 万一将来拿到 SDK，
放进 `sdk/lib/x86_64/` 重新构建即可直接出可用程序，工程部分不需要重做。

### 4.2 连「设备型号 ID」都要向华为申请

`driver_adapt.h`：

```c
typedef struct {
    char modelId[3];   /**< 设备型号ID, 向华为申请的用于查询设备信息的唯一标识, Nearby协议规定长度3个字节 */
    char subModelId;   /**< 设备子型号ID，用于区分不同外形特征的同款设备 */
    int  subModelFlag; /**< 标识设备是否有Sub-Model ID */
} DeviceModelId;
```

说明这套协议是**授权制**的：华为给第三方设备发 3 字节 model ID，手机侧据此识别「对面是什么设备」。

### 4.3 全网排查（2026-10-18 实测）

| 检查项 | 命令/来源 | 结果 |
|---|---|---|
| GitHub 全量代码搜索 `libsharekit` | `gh api search/code?q=libsharekit` | 67 条命中，**全是 iOS 同名 ShareKit**；唯一相关的是华为官方仓库自己的 `Linux/Makefile` |
| `sharekitdrx` | 同上 | 4 条，**全部**在 `huaweicodelabs/ShareEngine` |
| `StartShareService` | 同上 | 21 条，仅华为仓库的 `sharekit_api.h` / `sharekitdrx.c` 相关 |
| `sharekit_api.h` | 同上 | 6 条，全在华为仓库 |
| AUR `sharekit` | `aur/rpc/v5/search/sharekit` | **0 个包** |
| AUR `huawei` | `aur/rpc/v5/search/huawei` | 37 个包，无一与分享引擎相关（都是 modem/打印机/WMI 之类） |
| Arch 官方仓库 | `pacman -Ss huawei` | 无 |
| 本机 | `find /` | 无任何 `libsharekit*` |
| 国内 Gitee / CSDN | 网络搜索 | 无公开 SDK 副本 |

→ **没有任何公开的 `libsharekit.so`，也没有任何社区重实现。** 想要真正的「华为分享」，只剩「自己去申请」这一条路。

### 4.4 现实社区的普遍结论

俄语论坛讨论（Huawei MateBook D16 + Ubuntu，2025-01）里，发帖人问「Linux 上还有没有办法用 Huawei Share」，最高赞回答是：

> Это фишка Huawei.（这是华为的专属功能。）Воспользуйся, например, KDEconnect для телефона и gconnect для убунты.

即：社区默认「Linux 上没有华为分享，用 KDE Connect 之类替代」。
<https://www.linux.org.ru/forum/desktop/17852841>

我们这次调研比这个结论更进一步——**官方 SDK 是存在的**，只是有账号门槛。

## 5. 本机前置条件体检

| 项目 | 官方要求 | 本机现状 | 判定 |
|---|---|---|---|
| 架构 | x86_64 / arm64 | x86_64 | ✅ |
| BlueZ | 5.52（需源码编译内部库） | 系统 bluez（版本更高，但不含内部库） | ⚠️ 需自编译 5.52 |
| BlueZ 工具 | — | **缺 `bluez-utils`（没有 `bluetoothctl`）** | ❌ 待装 |
| 蓝牙硬件 | hci 设备 | `hci0` 存在，`bluetooth.service` active | ✅ |
| wpa_supplicant | 需要 P2P 支持 | 已安装，但 **service inactive**（当前用 iwd） | ❌ 需切换 |
| Wi-Fi P2P | 需要 | `wlan0` 支持；NetworkManager 已识别 wifi-p2p（走 iwd） | ⚠️ 通道要换 |
| OpenSSL | 1.1.1g | 系统 3.x | ⚠️ 待验（SDK 是 2019 年的，可能绑 1.1.1 符号） |
| glib-2.0 | 需要 | 有 | ✅ |

## 6. 推荐执行顺序

1. **先拿到 SDK**：注册华为开发者账号（需实名）→ 打开「Obtaining the Linux SDK」→ 下载 Linux 包 → 得到 `libsharekit.so`（`gcc/` 与 `aarch64/` 两个架构）与头文件。
   放进本仓库 `sdk/lib/` 与 `sdk/include/`。
2. `./scripts/check-sdk.sh` —— 校验拿到的库确实导出了 `InitShareKit`/`StartShareService` 等符号，架构也对。
3. `./scripts/build.sh` —— 自动拉取官方 demo、编译 BlueZ 5.52 内部库、编译我们的接收端 `hwshare-rx`。
4. 切换蓝牙/Wi-Fi 通道：停 iwd 接管、起 wpa_supplicant（带 P2P）、装 `bluez-utils`。
5. `sudo ./scripts/run-rx.sh` 起接收端；手机上打开「华为分享」→ 应该能看到这台电脑。
6. 装 `systemd/huawei-share-rx.service` 让它开机常驻。

如果第 1 步走不通（没有开发者账号 / SDK 已下架），走 `docs/替代方案.md`，今天就能传文件。
